# Luxicon for Mac Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native macOS Luxicon app that records in-person 1-on-1s on the laptop mic, processes them on-device, files them into the shared `~/Luxicon` library, imports the phone's voice print over the existing sync path, and ships as a Developer ID–signed, notarized DMG.

**Architecture:** A second xcodegen target, `LuxiconMac`, shares `App/Sources` with the iOS target. A handful of iOS-only files are excluded, and platform differences sit behind `#if os(...)` and a small `PlatformCompat.swift` shim. Mac-only code (split-view shell, library index, recording window, settings, onboarding) lives in `App/MacSources/`. The pure logic both apps depend on (export provenance, voice-print file, library filename, people merge) goes in LuxiconKit, where `swift test` covers it.

**Tech Stack:** Swift 6, SwiftUI (macOS 15+, iOS 18+), LuxiconKit/MLX, xcodegen, swift-testing, `xcodebuild`/`notarytool`/`stapler`/`hdiutil`.

**Spec:** `docs/superpowers/specs/2026-10-22-mac-app-design.md`

## Global Constraints

- Mac target: bundle ID `edu.davidson.luxicon.mac`, team `4Z539UE4TT`, `platform: macOS`, deployment target macOS 15.0, arm64 only, hardened runtime, no sandbox.
- Mac entitlements: `com.apple.security.device.audio-input` only.
- Shared version train: `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION` from `App/project.yml` project-level settings.
- Mac app state: `~/Library/Application Support/Luxicon/` (`store.json`, `audio/`, `photos/`). Never `~/Documents`.
- Shared library: `~/Luxicon/`. Create it if missing. Never write, rename, or delete a file there unless its envelope has `"source": "mac"`. `.sync-token` is read-only to the app.
- Voice-print file: `~/Luxicon/luxicon-voiceprint.json`, `kind: "voiceprint"`, `schemaVersion: 1`.
- Release names: `dist/Luxicon-<marketing>-<build>.dmg`, tag `mac-v<marketing>-<build>`. Publishing a GitHub release needs JD's explicit go-ahead.
- No new network paths. The Mac app makes no LAN connections. Its only network traffic is the existing first-run speech-model download and https vocabulary/people URL sync.
- `store.json` back-compat: new fields are optionals. Never rename keys.
- The iOS build must keep passing after every task: `cd App && xcodegen generate && xcodebuild -project Luxicon.xcodeproj -scheme Luxicon -destination 'generic/platform=iOS' -configuration Release -allowProvisioningUpdates build`.
- Tests stay offline. Only LuxiconKit has tests. App changes are verified by building and by screenshots.

## Review Focus

1. **The listener's library already holds a file the Mac also wrote.** When the phone pushes a session the Mac also recorded (impossible today) or the same filename collides, the Mac must not hide or overwrite the phone file. Task 5 pins this: the filter is by `sessionId`, and writes refuse to overwrite a non-Mac file.
2. **`store.json` is lost but Mac-written files remain.** They show as Mac sessions you can read or delete, never as editable or iPhone sessions. Covered by Task 2 tests on `LibraryMerge` and Task 5's orphan handling.
3. **The Mac sleeps or the mic disappears mid-recording.** On a lid close, AirPods disconnecting, or a USB mic unplugged, audio captured so far is never lost. Task 7: the sleep notification finalizes; a config change rewires; crash recovery is already in `Store`.
4. **A malformed or foreign `luxicon-voiceprint.json`** (wrong kind, wrong embedding length, or garbage) never crashes the app and never replaces an enrolled voice. Task 2 tests `VoicePrintFile.decode`, and Task 8 rejects dimension mismatches.
5. **A huge library or a rapid burst of pushes.** "Push All" can write dozens of files in a second. The watcher debounces (0.5 s), and the reload parses off the main actor. Task 5.
